# Intro artwork

The boarding sequence on the landing page loads these three files. Until all
three decode the intro is skipped entirely — the site is unaffected.

| File | What it must be |
|---|---|
| `plane.svg` | Side view, **pink**, open-top with visible seating |
| `traveller.png` | Man in a pagdi/turban, **side profile**, walking, with a suitcase |
| `couple.png` | Man and woman, **side profile**, walking together with bags |

**Transparent background**, and use one illustration style across all three or
they will not read as one scene.

## Size these correctly

The two characters render at **59 x 99 CSS px** at their largest — that is the
1920x1080 case, where the shared unit `--u` peaks at 11.79px and a character is
`0.6 x 0.72` of the plane's height. Ship them at **240 x 400**, which covers
that at DPR 4.

This matters more than it sounds. They were once shipped at 600x1000 (386 KB and
513 KB) — about 1% of those pixels ever reached a screen, and the intro cannot
start until both have decoded, so nearly 900 KB of download stood between a
visitor and the first frame. Resized to 240x400 they are 74 KB and 102 KB, with
no visible difference at any viewport the path is tested at.

If you change `--u`, `--plane-w` or the `0.72`/`0.6` character ratios in
`BoardingAnimation.css`, recompute the render size before re-exporting:

    node -e "import('./scripts/build-boarding-path.mjs').then(m=>{ \
      const u=Math.max(...Object.entries(m.VARIANTS).flatMap(([n,v])=> \
        m.VIEWPORTS.filter(([w,h])=>(w<=900&&h>=w)===(n==='portrait')) \
          .map(([w,h])=>m.unitPx(v,w,h)))); \
      const ph=0.72*m.PLANE_U/1.8*u; console.log((0.6*ph).toFixed(0)+' x '+ph.toFixed(0)); })"

## Facing

Both characters must face **RIGHT**, the way they walk. The plane artwork faces
left and is mirrored once, statically, by `scaleX(-1)` on `.boarding-plane__img`
— it flies rightward for the whole sequence and never changes direction, because
a direction change on a side-view sprite is always an instantaneous flip.

## Positioning

Geometry lives at the top of `src/features/landing/BoardingAnimation.css`; the
flight path itself is generated by `scripts/build-boarding-path.mjs` and must
not be hand-edited. The two seat offsets (`.boarding-seat--1`,
`.boarding-seat--23`) are percentages of the plane's own width and are the
mirrored values, so they will need nudging to match wherever the seats sit in
your art.
